The primary goal was to devise an original algorithmic methodology that could evaluate live game trends, anticipate opponent choices, adapt dynamically across consecutive iterations, and systematically outperform alternative student submissions and baseline randomized strategies.

Technical Description & Implementation:
My program establishes a specialized pattern recognition routine titled "pattern recognition". The algorithm acts dynamically by analyzing data captured across two native arrays: `my_history` and `their_history`. To prevent initial runtime execution out-of-bounds errors, the code deploys a protective conditional threshold that evaluates if the game iteration length is under two rounds; if true, it defaults to throwing a stable "paper" move, mitigating the common human bias of throwing "rock" on opening moves. For subsequent turns, my program checks historical entries using negative index indicators. It compares the opponent's immediate last move `their_history[-1]` to their second-to-last move `their_history[-2]`. If a matched double-move pattern is identified, it maps a variable `x` to target that input and returns its explicit mathematical counter. If no repetition is verified, it isolates their secondary historical choice `their_history[-2]` to interrupt standard sequence rhythms and bypass predictable feedback loops.

Project 2: CSE 3.1.3 Combo Menu Automated Ordering Terminal

Course: Computer Science Essentials (PLTW)

Date Completed: Spring 2026

Source Code View: Combo_Menuv4-2.py script structure

Official Project Objective & Goal:
The objective of this PLTW Computer Science Essentials project was to program a functional, user-facing, automated restaurant combo menu ordering system. The goal was to construct an application that collects user preferences across multiple categories (including main courses, beverages, sides, and item-specific quantities), dynamically computes financial sub-totals, alters pricing structures based on item dimension flags, automatically processes bundle promotional discounts, and displays calculated itemized invoices back to the consumer.

Technical Description & Implementation:
The software utilizes sequential `input()` query functions to systematically walk a consumer through ordering modules for sandwiches, drinks, fries, and ketchup. It initiates a floating accumulation variable `totalcost=0` to preserve the financial state across the runtime environment. The ordering blocks feature deeply nested execution branches. For instance, selecting a sandwich processes inputs for chicken ($5.25), beef ($6.25), or tofu ($5.75), appending the values to the cost accumulator. The drink and fry modules perform sub-tier size validations (small, medium, large), with the fry section executing an auxiliary sub-query to upcharge an extra $1.00 if a "mega-size" conditional override flag returns positive. To secure the terminal from breaking during numeric entries, a native string method `.isdigit()` filters the ketchup variable before explicit type-casting converts the string into an operational mathematical integer (`int(ketchup)`), allowing calculation of incremental packet fees ($0.25 each). Finally, the app tests a multi-variable logical condition: if a sandwich, drink, and fries are all active, it registers a bundle markdown, deducts $1.00 from the total, and presents the final formatted cost.

My Responsibilities, Learnings & Skills Exemplified:
I handled the complete codebase composition, variable assignment structures, and nesting formatting. I resolved data type alignment challenges by ensuring user response strings were cast to lowercase (`.lower()`) to eliminate input variability, and leveraged data string formatting techniques (`str(totalcost)`) to cleanly concatenate text data blocks with arithmetic primitives during console print outputs. This project highlights my abilities in system input handling, computational algorithms, syntax nesting rules, and state management logic.
